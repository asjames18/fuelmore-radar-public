# Free collector RPC investigation — 2026-09-20 UTC

Production endpoints are unchanged. These are sampled capability checks, not
uptime guarantees or proof that an endpoint supplies all historical events.

## PublicNode

Published endpoint: https://robinhood.publicnode.com/

The keyless endpoint returned chain 4663, but historical eth_call and both
historical/recent 2,000 and 50,000-block log queries required a personal archive
token. It cannot currently replace Radar's collector without additional setup.
Local Node fetch failed before receiving RPC; curl could reach the endpoint.
The archive rejection is the actual RPC result from curl, not a DNS inference.

## dRPC

Published endpoint: https://drpc.org/chainlist/robinhood-mainnet-rpc

Historical reads at block 63139884, recent contract reads, and snapshot hash
consistency passed. Six-item batching failed: the free endpoint allows only
three items. 10 and 100-block log samples passed; 1,000, 2,000 and 50,000-block
samples failed with a range-limit error. The reported error mentioned 10,000
blocks even for smaller queries; use observed behavior, not that message as a
promised limit.

100-block windows ending at 63139884 and 67517055 matched Robinhood's public
endpoint in pinned block hash, log count and canonical event digest. The first
contained one event and the latter was empty. Neither establishes full-history
completeness. The collector sends individual calls, so its validation can use
100-block ranges without the frontend's six-item batch requirement.

A manual non-main workflow option now selects drpc-free for collector validation,
with its own checkpoint cache key. The existing managed RPC capability probe
remains independent. Production publishing receives neither this override nor
the validation output. A successful full resumed collection is still required.
